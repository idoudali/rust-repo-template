# Releasing

Releases are automatic once commits land on `main`; nothing is published to crates.io.

1. Every push to `main` runs `release-plz.yml`. It opens or updates a **Release PR** that bumps the workspace version, `Cargo.lock`, and `CHANGELOG.md` from the conventional commits since the last tag.
2. Review and merge the Release PR like any other PR.
3. On that merge, release-plz pushes the tag `v<version>`.
4. The tag starts `release.yml`, generated by [dist](https://opensource.axo.dev/cargo-dist/). It builds the CLI natively for Linux (static musl, `x86_64` and arm64), macOS (arm64 and `x86_64`), and Windows, then creates the GitHub Release with archives, shell and PowerShell installers, `sha256` checksums, a `CycloneDX` SBOM, and build attestations.

## One-time setup

- Create a GitHub App with **contents** and **pull requests** write access, install it on the repo, and set the `RELEASE_APP_ID` variable and `RELEASE_APP_PRIVATE_KEY` secret. A tag or PR created with the default `GITHUB_TOKEN` does not start other workflows, so without the App the tag never reaches `release.yml` and CI does not run on the Release PR.
- Enable "Allow GitHub Actions to create and approve pull requests" in the repo settings.

## Pre-releases

To cut a release candidate, set the version by hand on a branch (for example `0.2.0-rc.1` in `[workspace.package]`), merge it, and let release-plz tag it; dist marks versions with a pre-release suffix as GitHub pre-releases.

## Changing what gets built

Edit `dist-workspace.toml`, then run `mise run dist-generate` and commit the regenerated `release.yml`. `release.yml` also runs on every PR and fails if it is out of date with the config. `mise run dist-plan` lists the artifacts.

## Bumping the toolchain

`toolchain-bump.yml` opens a PR each month that moves `rust-toolchain.toml` and `mise.toml` to the latest stable Rust; other tools are bumped by editing `mise.toml`. Either change rebuilds the toolchain image in CI under a new tag.
