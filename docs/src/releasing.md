# Releasing

A release is two commands run on an up-to-date `main`, with a PR merge between them; nothing is published to crates.io.

1. `mise run release` runs `release-plz update`, which bumps the workspace version, `Cargo.lock`, and `CHANGELOG.md` from the conventional commits since the last `v*` tag. It commits that to a `release/v<version>` branch, pushes it, and opens the release PR. To choose the version instead, pass it: `mise run release 0.2.0`.
2. Review and merge the release PR like any other PR.
3. Back on `main`, pull, then run `mise run release-tag`. It reads the version from `Cargo.toml`, checks `CHANGELOG.md` has its entry, and pushes the tag `v<version>`.
4. The tag starts `release.yml`, generated by [dist](https://opensource.axo.dev/cargo-dist/). It builds the CLI natively for Linux (static musl, `x86_64` and arm64) and macOS (arm64), then creates the GitHub Release with archives, a shell installer, `sha256` checksums, a `CycloneDX` SBOM, and build attestations.

Both commands are `tools/release.sh` and refuse to run unless the working tree is clean and `main` matches `origin/main`. The tag is pushed with your own credentials, so it starts `release.yml` without a GitHub App or token secret.

## Pre-releases

Pass a version with a pre-release suffix, for example `mise run release 0.2.0-rc.1`; dist marks such versions as GitHub pre-releases.

## Changing what gets built

Edit `dist-workspace.toml`, then run `mise run dist-generate` and commit the regenerated `release.yml`. The `dist-check` git hook, which CI also runs, fails if `release.yml` is out of date with the config. `mise run dist-plan` lists the artifacts.

## Bumping the toolchain

`mise run toolchain-bump` (from an up-to-date `main`) opens a PR that moves `rust-toolchain.toml`, `mise.toml` and `mise.lock` to the latest stable Rust; other tools are bumped by editing `mise.toml`. Dependabot does not track the toolchain, so run it when a new stable Rust ships. Either change rebuilds the toolchain image in CI under a new tag.
